music-tui Song 页（歌词）开发手册 · 具体版 v2
================================================================
目标：左侧队列不变，右侧显示歌词，当前播放行高亮并自动滚动。

本版新增：歌词统一放在 ~/Music/lrc/ 下，按"镜像目录"查找。
这一版仍然只做最小闭环：读本地 .lrc -> 解析 -> 显示 -> 高亮 -> 滚动。
预计 3 次坐下完成（每次 1~2 小时）。


零、这一版不做什么
----------------------------------------------------------------
先不做：
  - 用户手动滚动时暂停跟随；
  - 歌词偏移快捷键；
  - 联网搜索/下载歌词；
  - 内嵌标签歌词（mutagen）；
  - 逐字卡拉 OK。

只做：
  本地 .lrc -> 解析 -> LyricsPane -> 当前行高亮 + 自动居中滚动。

三、歌词目录设计（先定下来）
----------------------------------------------------------------
【卡 0.1】目录布局（现在）

  ~/Music/                                  <- MPD 的 music_directory
  ├── 松下優也 - Mr.“Broken Heart”.mp3
  ├── Michita - Cry For Me (feat. Ami).mp3
  ├── 王忻辰&苏星婕-去年花开.flac
  └── lrc/                                  <- 歌词集中放这里
      ├── 松下優也 - Mr.“Broken Heart”.lrc
      ├── Michita - Cry For Me (feat. Ami).lrc
      └── 王忻辰&苏星婕-去年花开.lrc

  说明：
    - lrc/ 放在 Music 里面，路径直观，和音乐同盘同备份；
    - .lrc 不是音频，MPD 不会把它加入播放队列；
    - 以后如果 MPD 的库列表里真的出现了 .lrc，也不影响播放，
      只是一个无法播放的条目，可以忽略。

【卡 0.2】路径规则：镜像相对路径

  规则：歌词路径 = LRC_DIR / 音频相对路径，只把后缀换成 .lrc

  例：
    uri = "Michita - Cry For Me.mp3"
      -> ~/Music/lrc/Michita - Cry For Me.lrc

    uri = "专辑A/01 - 晴天.mp3"
      -> ~/Music/lrc/专辑A/01 - 晴天.lrc

  优点：
    - 规则简单，一眼能算出路径；
    - 不同专辑有同名歌曲时不会冲突（子目录不同）；
    - 以后加专辑目录，代码不用改。

  实现位置：core/lyrics.py
  函数签名：
    def lyrics_path(uri: str) -> Path:
  内部用：
    LRC_DIR / Path(uri).with_suffix(".lrc")

【卡 0.3】需要每次扫描 lrc 文件夹吗？不需要

  查找是"算路径 + 判断是否存在"，O(1)：
    lrc = lyrics_path(uri)
    if not lrc.exists(): ...

  不需要：
    - 启动时扫描 lrc/ 建索引；
    - 监听文件系统变化；
    - 增删歌曲后同步索引。

  扫描只在"维护"时需要（比如清理孤儿 lrc），
  那是以后的一个独立小工具，不在播放路径上。

【卡 0.4】增删歌曲时会发生什么

  新增歌曲：
    1. 音频放进 ~/Music（以后放进专辑目录）；
    2. 把 .lrc 放到 lrc/ 对应的镜像路径；
    3. 不需要改任何代码，切到那首歌时自然能读到。
    如果暂时没有 .lrc，显示"暂无歌词"，不报错。

  删除歌曲：
    1. 删音频；
    2. lrc/ 里对应的文件会变成"孤儿"；
    3. 孤儿没有任何影响，可以以后写个清理工具统一删。

  重命名/移动歌曲：
    音频和 lrc 要一起改。
    这是镜像方案唯一的额外成本。
    （如果以后想省这一步，可以改成"按 URI 哈希命名"，
      但文件名不可读，不推荐。）

【卡 0.5】以后加专辑目录

  现在：
    ~/Music/歌.mp3
    ~/Music/lrc/歌.lrc

  以后：
    ~/Music/专辑A/01.mp3
    ~/Music/lrc/专辑A/01.lrc

  路径规则不变，load_lyrics 不用改一行代码。

【卡 0.6】建目录 + 造测试歌词

  1. 建目录：
       mkdir -p ~/Music/lrc

  2. 选一首歌，建同名 .lrc：
       音频：~/Music/Michita - Cry For Me (feat. Ami).mp3
       歌词：~/Music/lrc/Michita - Cry For Me (feat. Ami).lrc

  3. 先写 10~20 行，每 4 秒一行，方便快速看到滚动：
       [00:00.00]第一行
       [00:04.00]第二行
       [00:08.00]第三行
       ...

  4. 可选自查：MPD 会不会把 .lrc 当歌曲
       touch ~/Music/lrc/__probe.lrc
       mpc update
       mpc ls | grep __probe
       rm ~/Music/lrc/__probe.lrc
     预期没有输出；如果有，也不影响播放。


四、卡 1：数据模型（core/lyrics.py）
----------------------------------------------------------------
文件顶部需要：
  from dataclasses import dataclass
  from bisect import bisect_right
  from pathlib import Path
  import re
  from music_tui.config import LRC_DIR

【1.1】LyricLine

  @dataclass(frozen=True)
  class LyricLine:
      time_ms: int
      text: str

  说明：
    frozen=True 让对象不可变，排序、比较都安全。
    只放数据，不要放"是否当前行"这种 UI 状态。

【1.2】文件内布局：什么在类里，什么在模块级

  core/lyrics.py 从上到下长这样（注意缩进）：

    @dataclass(frozen=True)
    class LyricLine:                          <- 类：只放字段
        time_ms: int
        text: str

    def lyrics_path(uri: str) -> Path:        <- 模块级，顶格（第 1 列）
        ...

    def parse_lrc(text: str) -> list[LyricLine]:   <- 模块级，顶格
        ...

    def index_at(lines: list[LyricLine], position_ms: int) -> int:  <- 模块级
        ...

    def load_lyrics(uri: str) -> list[LyricLine] | None:  <- 模块级
        ...

  判断标准：

    顶格（第 1 列）  -> 模块级函数，import 时用：
                        from music_tui.core.lyrics import parse_lrc
    缩进 4 空格      -> 类的方法，必须通过类或实例访问

  LyricLine 里只放 time_ms / text 两个字段。
  lyrics_path、parse_lrc、index_at、load_lyrics 全部顶格。
  把这四个函数缩进到 class 里面是错的——那样 import 不进来。


五、卡 2：解析函数 parse_lrc
----------------------------------------------------------------
【2.1】签名

  def parse_lrc(text: str) -> list[LyricLine]:

  参数：整个 .lrc 文件的文本
  返回：按 time_ms 升序的列表；没有有效行时返回 []

【2.2】要处理的格式

  [00:12.34]歌词内容
  [00:01.00][00:05.00]重复的副歌
  [ti:歌名] [ar:歌手] [al:专辑]
  [offset:+300]

【2.3】会用到的内置函数 / 方法

  text.splitlines()                     按行拆分
  line.strip()                          去首尾空白
  re.match(pattern, line)               从行首匹配，返回 match 或 None
  re.finditer(pattern, line)            找全部匹配，返回迭代器
  match.group(1) / group(2) / group(3)  取分组
  match.end()                           匹配结束位置
  int("12")                             字符串转整数
  str.ljust(3, "0")                     右边补 0
  result.append(...)                    收集结果
  result.sort(key=lambda x: x.time_ms)  排序

【2.4】先建立模型：逐行分类

  不要一上来想整个函数。把每一行想成四种之一：

  类型        例子                  处理
  空白行      ""  "   "             跳过
  元数据行    [ti:歌名] [ar:歌手]   跳过
  offset 行   [offset:+300]         记下数字，继续
  歌词行      [00:12.34]歌词        提取时间 + 正文

  整个函数 = 一个 for 循环 + 四个分支。

【2.5】判断顺序（不能乱）

  每行按这个顺序检查：

    1. strip() 去空白
    2. 是空行？        -> continue
    3. 是 offset 行？  -> 记下 offset，continue
    4. 有时间戳吗？    -> 没有就 continue（元数据）
    5. 有 -> 提取正文，生成记录

  为什么 offset 要排在时间戳前面：
    [offset:+300] 里没有时间戳。如果先判断时间戳，它会被当成元数据跳过，
    offset 永远读不到。

【2.6】空白行怎么判断

  line = raw.strip()
  if not line:
      continue

  原理：
    "   ".strip() 得到 ""；
    Python 里空字符串是"假值"，not "" 是 True。

  等价写法：if line == "": continue。

【2.7】offset 行怎么判断

  m = re.match(r"\[offset:\s*([+-]?\d+)\s*\]", line)
  if m:
      offset = int(m.group(1))
      continue

  拆开看：

    re.match        从行首匹配（开头的 [ 必须在第 0 位）
    \[ \]           匹配字面量方括号
    offset:         固定文字
    \s*             允许冒号前后有空格
    ([+-]?\d+)      捕获组：可选正负号 + 数字
    m.group(1)      取捕获的字符串，如 "+300"
    int("+300")     得到 300；int("-200") 得到 -200

  例子：

    [offset:+300]   -> 匹配，300
    [offset: -200]  -> 匹配，-200
    [ti:歌名]       -> None
    歌词 [offset:1] -> None（不在行首）

  注意：re.match 只看开头；找多个时间戳要用 finditer。

【2.8】歌词行：找时间戳

  stamps = list(re.finditer(
      r"\[(\d{1,3}):(\d{1,2})(?:[.:](\d{1,3}))?\]",
      line,
  ))
  if not stamps:
      continue

  为什么先转 list：
    finditer 返回迭代器，只能遍历一次；后面既要数个数，又要取最后一个的
    end()，所以先转成列表。

  每个 match 的常用属性（以 [00:40.00] 为例）：

    group(1)  分钟 "00"
    group(2)  秒   "40"
    group(3)  毫秒 "00"；没有小数部分时是 None
    end()     这个时间戳在行里的结束位置

【2.9】提取正文

  text = line[stamps[-1].end():].strip()

  line[10:] 就是"从第 10 个字符切到结尾"。

  例子：

    [00:40.00][00:44.00]副歌：Cry for me
                     ↑
               最后一个 match 的 end 在这里

  切出来就是 "副歌：Cry for me"。

【2.10】毫秒补齐

  ms_str = stamp.group(3) or "0"
  ms = int(ms_str.ljust(3, "0"))

  group(3) 可能是 None（比如 [00:12] 没有小数），所以先 or "0"。
  ljust(3, "0") = 右边补 0 到长度 3：

    原始    补齐后    毫秒
    "5"     "500"     500
    "50"    "500"     500
    "500"   "500"     500
    "05"    "050"     50
    "0"     "000"     0

【2.11】算总毫秒

  minutes = int(stamp.group(1))
  seconds = int(stamp.group(2))
  time_ms = minutes * 60000 + seconds * 1000 + ms - offset

  offset 约定：[offset:+500] 表示歌词整体提前 500ms，所以减。

【2.12】最后排序

  result.sort(key=lambda item: item.time_ms)

  两个原因：
    1. 文件本身可能乱序；
    2. index_at 用二分查找，前提是有序。

  key 指定"按哪个字段比较"，lambda item: item.time_ms 就是取 time_ms。

【2.13】拿四行真实数据走一遍

  假设初始 offset = 0。

  第 1 行 "   "：
    strip() -> ""
    not "" -> True
    continue

  第 2 行 "[ti:去年花开]"：
    strip() -> 原样
    不是空行
    re.match(offset) -> None
    finditer(时间戳) -> 空列表
    if not stamps -> continue

  第 3 行 "[offset:+500]"：
    strip() -> 原样
    不是空行
    re.match -> 匹配
    offset = int("+500") = 500
    continue

  第 4 行 "[00:40.00][00:44.00]副歌"：
    strip() -> 原样
    不是空行
    offset 正则 -> None
    finditer -> 两个 match
    stamps[-1].end() -> 指向 "副歌" 前面
    text = "副歌"
    第一个 match：40*1000 - 500 = 39500
    第二个 match：44*1000 - 500 = 43500
    result 加两条：LyricLine(39500, "副歌")、LyricLine(43500, "副歌")

  最后 sort。

【2.14】常见坑

  坑                              后果                            正确做法
  用 re.findall 取时间戳          拿不到 end()，不知道正文从哪切   用 finditer
  用 re.match 找时间戳            只匹配行首第一个，漏掉后面的      用 finditer
  offset 判断放在时间戳后面       offset 被当元数据跳过            offset 先判断
  int(group(3)) 直接调用          没有毫秒时 None 报错             group(3) or "0"
  忘了排序                        二分查找结果错乱                 最后统一 sort

【2.15】写代码之前先手算

  拿这几行走一遍，写下中间值：

    [ti:测试]
    [offset:+500]

    [00:01.00][00:05.50]副歌
    [00:10.00]第二句

  期望结果：

    LyricLine(500,  "副歌")     # 1000 - 500
    LyricLine(5000, "副歌")     # 5500 - 500
    LyricLine(9500, "第二句")   # 10000 - 500

  手算对了再写循环；写出来先跑这个例子的单测，通过后再处理真实文件。

【2.16】边界

  - 一行多个时间戳：每个生成一条；
  - 格式不完整的行：finditer 找不到，按元数据跳过；
  - 负 time_ms：保留，index_at 会处理；
  - 空文本：返回 []；
  - 文件带 BOM：读取时用 encoding="utf-8-sig"，否则第一行时间戳可能匹配失败；
  - CRLF 换行：splitlines() 会自动处理，不用自己删 \r。

【2.17】五个最容易写错的地方（对照检查）

  错误 1：把列表当 match 用
    ms_str = stamps.group(3)          # ✗ stamps 是 list，没有 group
    minutes = int(stamps.group(1))    # ✗ 同上
  正确：
    先切正文：content = line[stamps[-1].end():].strip()
    再遍历每个时间戳：for stamp in stamps:
        用 stamp.group(1) / group(2) / group(3)

  错误 2：忘记 append
    time_ms = ...
    result.sort(...)                  # ✗ 算了但没放进 result
  正确：
    result.append(LyricLine(time_ms, content))

  错误 3：sort 的 key 写错，而且放在循环里
    result.sort(key=lambda item: time_ms)   # ✗ time_ms 是局部变量
  正确：
    循环结束后只排一次：
    result.sort(key=lambda item: item.time_ms)

  错误 4：index_at 里调用 lines.parse_lrc()
    lines.parse_lrc()                 # ✗ list 没有这个方法
  正确：
    删掉这一行。lines 传进来时已经是 parse_lrc 的结果。

  错误 5：text 被反复覆盖
    text = line[stamps[-1].end():].strip()  # ✗ 覆盖了函数参数 text
  正确：
    content = line[stamps[-1].end():].strip()

【2.18】循环骨架：先理清顺序再写

  result = []
  offset = 0

  for raw in text.splitlines():
      line = raw.strip()

      1. 空行 -> continue
      2. offset 行 -> 记录 offset，continue
      3. stamps = list(finditer(时间戳, line))
         如果为空 -> continue
      4. content = line[stamps[-1].end():].strip()
      5. for stamp in stamps:              <- 遍历 stamps，不是遍历 list 本身
             minutes = int(stamp.group(1))
             seconds = int(stamp.group(2))
             ms = int((stamp.group(3) or "0").ljust(3, "0"))
             time_ms = minutes*60000 + seconds*1000 + ms - offset
             result.append(LyricLine(time_ms, content))   <- 每条都 append
  6. result.sort(key=lambda item: item.time_ms)           <- 循环外，只排一次
  7. return result

  记忆点：
    - "提取正文"在循环 stamps 之前做一次；
    - "append"在循环 stamps 里面，每条时间戳一次；
    - "sort"在两层循环都结束之后。

【2.19】写完后先跑这个验证

  .venv/bin/python -c "
  from music_tui.core.lyrics import parse_lrc
  lines = parse_lrc('[offset:+500]\n[00:01.00][00:05.50]副歌\n[00:10.00]第二句')
  print([(l.time_ms, l.text) for l in lines])
  "

  预期：

    [(500, '副歌'), (5000, '副歌'), (9500, '第二句')]

  对不上时按这个顺序查：
    - 第一条是 1000 而不是 500 -> offset 没减；
    - 只有两条而不是三条     -> 没有遍历 stamps，只处理了最后一个；
    - 顺序不对               -> sort 不在循环外，或 key 写成了 time_ms。


六、卡 3：按时间找当前行 index_at
----------------------------------------------------------------
【3.1】签名

  def index_at(lines: list[LyricLine], position_ms: int) -> int:

  返回：
    -1        还没到第一句
    0..n-1    当前行
    n-1       超过最后一句时停在最后

【3.2】用二分

  from bisect import bisect_right

  思路：
    i = bisect_right(lines, position_ms, key=lambda l: l.time_ms) - 1
    if i < 0: return -1
    return i

  说明：
    bisect_right 返回"第一个大于 position_ms 的位置"；
    减 1 就是"最后一句小于等于当前位置"的行号。

【3.3】边界

  - lines 为空：先 return -1（否则 bisect 也能跑，但语义要明确）；
  - position_ms 为负：返回 -1；
  - lines 必须已排序。


七、卡 4：歌词路径 + 加载
----------------------------------------------------------------
【4.1】配置常量

  在 src/music_tui/config/__init__.py 写：

  from pathlib import Path

  MUSIC_DIR = Path.home() / "Music"
  LRC_DIR = MUSIC_DIR / "lrc"

  以后做配置文件时，再换成读取 TOML。

【4.2】lyrics_path

  签名：def lyrics_path(uri: str) -> Path:

  实现：return LRC_DIR / Path(uri).with_suffix(".lrc")

  说明：
    - uri 是 MPD 给的相对路径；
    - with_suffix 只替换最后一段后缀，.flac / .m4a 同样适用；
    - uri 里如果有子目录，会自动带入（镜像结构）。

【4.3】load_lyrics

  签名：def load_lyrics(uri: str) -> list[LyricLine] | None:

  参数：uri，MPD 的相对路径
  返回：
    解析成功 -> list[LyricLine]
    文件不存在 -> None

  注意：不再需要 music_dir 参数，LRC_DIR 从 config 读。

  步骤：
    1. lrc = lyrics_path(uri)
    2. if not lrc.exists(): return None
    3. 依次尝试读取：
         text = lrc.read_text(encoding="utf-8")
       失败（UnicodeDecodeError）再试 gbk；
       再失败用 encoding="utf-8", errors="replace"
    4. return parse_lrc(text)

【4.4】可用的内置函数 / 方法

  Path / 运算符                    路径拼接
  Path.with_suffix(".lrc")        换后缀
  Path.exists()                   是否存在
  Path.read_text(encoding=...)    一次读完
  except UnicodeDecodeError:      换编码
  except OSError:                 读不了时返回 None

【4.5】边界

  - 文件存在但为空：parse_lrc 返回 []，界面显示"暂无歌词"；
  - uri 含中文/空格：Path 正常处理，不用手动转义；
  - 不要把所有异常都吞成 None，编码问题和文件问题分开处理，
    方便排查。

  def test_parse_single_line() -> None:

  def test_parse_sorts_output() -> None:

【5.6】关于 monkeypatch 的两点说明

  1. 为什么用 monkeypatch，不直接改配置：
     改全局会让后面的测试也受影响；monkeypatch 会在每个测试结束后
     自动还原。

  2. 为什么 setattr 的字符串是 "music_tui.core.lyrics.LRC_DIR"：
     lyrics.py 里是 from music_tui.config import LRC_DIR，
     名字被复制进了 lyrics 模块；要改的是"lyrics 模块里那个名字"，
     不是 config 里的。如果改成 "music_tui.config.LRC_DIR"，不生效。

九、卡 6：LyricsPane 控件
----------------------------------------------------------------
【6.1】目标

  做一个只负责显示的控件：给它歌词和当前时间，它负责
  "高亮哪一行"和"滚到哪里"，不碰文件、不碰 MPD、不碰 App 状态。

  结构（控件树，不是代码）：

    LyricsPane(Pane)
      └── VerticalScroll#lyrics-scroll
            ├── 第 1 行 Static（class="lyric"）
            ├── 第 2 行 Static
            └── ...

  为什么每行一个 Static：
    长句会自动换行。用一个大 Static 装所有行时，
    "歌词第 N 行"和"屏幕第 N 行"对不上，滚动会偏。

【6.2】你需要自己维护的三个状态

  字段        类型                含义
  _lines      list[LyricLine]     当前歌词数据
  _rows       list[Static]        和 _lines 一一对应的控件
  _current    int                 当前高亮行，-1 表示没有

  规则：
    - 三者必须同步；_rows 和 _lines 长度不一致，高亮就会指错行；
    - 每次 set_lines 都要把 _current 重置为 -1。

【6.3】要实现的方法（只给签名和职责）

  1) compose(self) -> ComposeResult

     返回一个 VerticalScroll，id 固定为 lyrics-scroll。
     不要在这里创建歌词行。

  2) set_lines(self, lines: list[LyricLine]) -> None

     要做的事：
       - 清空旧行；
       - 按 lines 重新创建行控件；
       - lines 为空时显示"暂无歌词"；
       - 重置 _lines / _rows / _current。

  3) set_position(self, position_ms: int) -> None

     要做的事：
       - 用 index_at 算出当前行；
       - 和 _current 相同就直接返回（避免每 100ms 重画）；
       - 不同则：取消旧行高亮、设置新行高亮、滚动到新行；
       - idx < 0（还没到第一句）时不点亮任何行。

  4) on_resize(self) -> None（可选）

     第一版可以不做。如果窗口尺寸变化后滚动位置不对，
     再在这里重新滚动到当前行。

【6.4】可用的 API

  self.query_one("#lyrics-scroll", VerticalScroll)
  Container.mount(widget)
  Container.mount_all(list_of_widgets)
  Widget.remove_children()
  Widget.set_class(True/False, "current")
  ScrollView.scroll_to_widget(widget, animate=False, center=True)

  说明：
    - mount / mount_all / remove_children 返回 awaitable，
      但可以直接调用，不需要 await；
    - scroll_to_widget 的 center=True 会把目标行放在中间。

【6.5】需要你自己想清楚的边界

  - 第一次 set_position 时 _current 是 -1，没有旧行需要取消高亮；
  - position 在第一句之前，index_at 返回 -1，不能去取 _rows[-1]；
  - 同一行反复到达，必须直接返回，不能每次重画；
  - 空歌词时 set_position 不能崩（_rows 为空）；
  - 切换页面时控件可能暂时隐藏，set_lines 仍应正常工作；
  - 长行换行后滚动定位是否还准？不准的话考虑截断或调整行高。

【6.6】CSS（可以直接用）

  #lyrics-scroll { height: 1fr; }
  .lyric { color: $text-muted; }
  .lyric.current { color: $text; text-style: bold; }
  #song-page { width: 1fr; height: 1fr; }

  说明：
    #song-page 是 LyricsPane 在 ContentSwitcher 里的 id，
    不撑满的话切页后高度可能是 0。

【6.7】验收（先不接 MPD）

  [ ] 行控件数量等于歌词行数
  [ ] 位置推进时，只有当前行有 current 类
  [ ] 当前行会滚到可视区中间
  [ ] 传空列表时显示"暂无歌词"，不崩
  [ ] 位置倒退时也能正确回退高亮
  [ ] 同一位置连续调用 10 次，界面不闪

【7.2】新增 _maybe_load_lyrics

  签名：def _maybe_load_lyrics(self) -> None:

  照抄 _maybe_load_cover 的结构：
    1. if self.svc is None or self._last is None: return

十二、卡住时怎么排查
----------------------------------------------------------------
  1. 歌词不显示：
     a. 打印 lyrics_path(uri) 的结果，路径对不对；
     b. 确认文件真的存在（ls 一下）；
     c. 打印 load_lyrics 的返回值，是 None 还是 []；
     d. 打印 _lyrics_uri，有没有被赋值。
  2. 显示了但不高亮：
     a. 打印 index_at 的返回值；
     b. 检查 _rows 长度和 idx 是否越界；
     c. 检查 CSS 类名是不是 "current"。
  3. 高亮但没滚动：
     a. 确认 query_one("#lyrics-scroll") 没抛异常；
     b. 确认传进 scroll_to_widget 的 row 是 _rows 里的同一个对象。
  4. 切页后歌词消失：
     a. 检查 #song-page 是否有 height: 1fr；
     b. 检查是否在切页时误调了 set_lines([])。
  5. 路径不对：
     a. uri 里有没有子目录；
     b. 文件名里的空格/中文是否和音频完全一致（包括全角符号）。
