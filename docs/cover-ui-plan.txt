music-tui Cover 界面开发计划
================================================================

一、目标
----------------------------------------------------------------
Cover 页布局：左 7 / 右 3。
  左边：正在播放歌曲的封面，用黑白字符（braille）重画。
  右边：歌曲列表（与 Song 页是同一个列表，切歌、选中状态同步）。

核心决定：两个页面共用【同一个 QueuePane 实例】，不是各建一个。
  做法：在 #body 里移动它的位置，而不是复制它。
  好处：selected、_songs、滚动位置、焦点全部自动保留，不需要同步代码。


二、总体结构
----------------------------------------------------------------
Horizontal#body
├── QueuePane#queue            <- 同一个实例，位置会变
└── Vertical#right
    └── ContentSwitcher#pages
        ├── song-page          （歌词，暂用占位）
        ├── cover-page         （CoverPane，黑白封面）
        └── visualization-page （以后做）

页面与布局对照：
  页面           子控件顺序            宽度
  song           [queue, right]        1 : 1
  cover          [right, queue]        7 : 3
  visualization  隐藏 queue            right 占满（以后）


三、第一步：布局与左右互换
----------------------------------------------------------------
【卡 1】CSS

  #body.cover-mode #queue { width: 3fr; }
  #body.cover-mode #right { width: 7fr; }

  原有的默认值保留，作为 song 页的比例：

  #queue { width: 1fr; }
  #right { width: 1fr; }

  注意：3fr + 7fr 是比例，不是固定列数。
  120 列终端下：列表约 36 列，封面约 84 列。
   80 列终端下：列表约 24 列，封面约 56 列。


【卡 2】_switch_page 末尾加三件事

  位置：switcher.current = page_id 之后。

  1. 取控件：
       body  = self.query_one("#body")
       queue = self.query_one("#queue")
       right = self.query_one("#right")

  2. 根据页面决定顺序：
       cover 页：body.move_child(right, before=queue)
       其他页  ：body.move_child(queue, before=right)

  3. 切换宽度比例：
       body.set_class(page_id == "cover-page", "cover-mode")

  可用 API：
       body.move_child(子控件, before=另一个子控件)
       body.set_class(条件, "类名")

  注意：move_child 只对【直接子控件】有效。
        #queue 和 #right 都是 #body 的直接子控件，没问题。


【卡 3】第一步验收（先不要做封面渲染）

  [ ] song 页：列表在左，占一半。
  [ ] cover 页：列表在右，占 3/10；左侧是占位文字。
  [ ] 切回 song：列表回到左边。
  [ ] 两页切换后，选中的歌、列表内容都不变。
  [ ] cover 页按 上/下/回车/空格 都正常（证明是同一个实例）。

  如果切换后键盘没反应，说明焦点丢了：
  在 _switch_page 末尾补一句
      self.set_focus(self.query_one("#queue"))


四、第二步：黑白字符封面
----------------------------------------------------------------
把 widgets/cover.py 里 CoverPane._redraw 的渲染方式
从"彩色半块"改成"黑白 braille"。
set_cover() 和 on_resize() 保持不变。

为什么用 braille：
  半块字符：每字符 2 个像素；84×20 的区域 = 84×40 像素。
  braille ：每字符 8 个点（2×4）；84×20 的区域 = 168×80 点。
  黑白情况下，braille 的分辨率是半块的 4 倍。


【卡 4】_redraw 的算法步骤

  1. self.cover 是 None -> 显示 "[dim]♪ no cover[/]"，return。

  2. 取 self.size 的 width / height；任一为 0 -> return。

  3. 转灰度并增强对比：
       gray = self.cover.convert("L")
       gray = ImageOps.autocontrast(gray)

  4. 缩放到点阵尺寸：
       点阵宽 = width  * 2
       点阵高 = height * 4
       用 Image.Resampling.LANCZOS。

  5. 用 ImageOps.contain 缩到点阵内，再贴到【白底】画布中央：
       白底 = 不点灯 = 留空。
       不要用黑底：黑底会被当成"深色像素"，整块变成点。

  6. 双重循环生成字符：
       for y in range(height):
           for x in range(width):
               每个字符对应 2×4 个点
               点阵坐标 (x*2+dx, y*4+dy)
               像素值 < 阈值（例如 128）就把对应 bit 置 1
               字符 = chr(0x2800 + bits)
           行末加换行（最后一行不加）

  7. body.update(整个字符串)

  braille 的 8 个点与 bit 对应（标准编码，直接照抄）：

      点位置 (dx, dy)      bit
      (0, 0)              0x01
      (0, 1)              0x02
      (0, 2)              0x04
      (1, 0)              0x08
      (1, 1)              0x10
      (1, 2)              0x20
      (0, 3)              0x40
      (1, 3)              0x80

  颜色说明：
      braille 字符使用终端前景色，默认是主题文字色，
      暗色主题下显示为亮色点，天然是黑白效果。

  CSS 补充（封面页内容左上对齐）：
      #cover-page .pane-body { content-align: left top; }


【卡 5】渲染验收（先不接 MPD）

  用本地一张 jpg 调 set_cover(open(路径, "rb").read())：

  [ ] 能看到图（线稿类封面清晰，照片类像报纸印刷）。
  [ ] 窗口拉大/缩小，图会重排。
  [ ] 没有封面时显示 "♪ no cover"。
  [ ] 图像不变形（用 contain，不拉伸）。


五、第三步：接线
----------------------------------------------------------------
【卡 6】把 Cover 页的占位换成控件

  1. compose 里：
       Static("[dim]cover page[/]", id="cover-page")
     换成
       CoverPane("cover", id="cover-page")

  2. 加回 import：
       from music_tui.widgets.cover import CoverPane

  3. _pump 的 CoverEvent 分支：
       先 self._cover_data = ev.data
       再 self.query_one(CoverPane).set_cover(ev.data)

  4. _maybe_load_cover 的清空分支：
       先 self._cover_data = None
       再 self.query_one(CoverPane).set_cover(None)

  隐藏状态下调用 set_cover 是安全的：
     页面隐藏时尺寸是 0×0，_redraw 会直接 return；
     切到 cover 页时 Textual 会发 Resize 事件，
     on_resize 会自动补画。

七、常见坑
----------------------------------------------------------------
1. 不要建两个 QueuePane。
   两个实例会导致 query_one 找到多个、选中状态不同步、要写额外同步代码。

2. move_child 之后注意焦点。
   如果键盘失效，set_focus 回 #queue。

3. 白底 vs 黑底。
   braille 把"深色像素"变成点；白底画布才能让留白真的空着。

4. 隐藏页面尺寸为 0，不要在这个状态下算图。
   _redraw 开头判断宽高是否为 0。

5. 阈值不要写死一个值就完事。
   线稿类封面用 128 通常就干净；
   照片类如果细节丢失，可以试 100~150，或加有序抖动（Bayer）。

6. 不要在每次 StatusEvent 里重画封面。
   只在切歌时 set_cover；窗口变化交给 on_resize。

7. 旧的彩色半块代码如果不用了，就删掉，避免两套渲染逻辑并存。
   如果以后想加"彩色模式"，再用参数区分，不要复制粘贴两份 _redraw。
